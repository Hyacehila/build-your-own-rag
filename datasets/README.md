# 数据集

[返回项目首页](../README.md) · [成品示例](../examples/README.md) · [贡献指南](../CONTRIBUTING.md)

这里收录教程使用的开源数据集，以及作者个人提供或整理的数据。符合分发条件的小型完整数据集优先随仓库提供，便于读者取得与教程一致的数据。每个数据集独立记录来源和许可，项目的 MIT 与 CC BY 4.0 不自动覆盖数据文件。

个人提供或整理的数据也需要说明其来源、制作或整理过程及适用许可。原创数据由提供者明确授权；包含第三方材料时，保留相应的来源与许可说明，详见[授权范围](../LICENSING.md#适用范围)。

## 目录约定

每个数据集放在 `datasets/<dataset-slug>/`。复制[数据集说明模板](../templates/dataset-readme.md)作为该目录的 `README.md`，实际加入数据时创建以下文件：

```text
<dataset-slug>/
  README.md        来源、许可、格式与使用说明
  LICENSE          数据适用的许可全文（保留上游要求的声明）
  SHA256SUMS       实际分发文件的 SHA-256 校验值
  data/            随 Git 分发的数据文件
```

上游有多个许可或其他必需的版权、署名文件时，一并保留并说明适用范围。原创数据没有上游版本时，填写作者、制作日期及本次分发版本，不编造上游信息。上述结构是约定，当前不创建虚构的数据或校验值。

## 分发规则

1. 核对数据来源、作者、版本和许可，说明允许再分发的依据。许可不明或不允许再分发时，仅保留来源和获取说明，不提交数据文件。
2. 许可允许且单文件、单个数据集总量均低于 **50 MiB** 时，优先将完整数据放入 `data/`。`1 MiB = 1,048,576` 字节；总量按待分发数据文件的实际字节数累加，不包括说明和许可文件。
3. 单文件或单个数据集总量达到 **50 MiB** 时，将该数据集完整分发包放到 GitHub Releases。仓库保留说明、许可、实际下载地址、文件大小和校验值；发布前不生成虚构下载链接。当前不启用 Git LFS。
4. Releases 分发包使用版本化文件名并包含数据及必要的许可与来源说明。Git 仓库中的 `SHA256SUMS` 记录下载包的实际文件名与校验值；不得用同名新内容替换既有版本。
5. 数据清洗、筛选、转换或抽样时记录处理步骤；如有处理脚本，随数据说明提供源码或明确链接。保留上游协议要求的声明，不将处理后的第三方数据改标为项目默认协议。
6. 数据更新时同步版本、文件大小、样本量、处理记录和校验值，检查关联示例是否仍可使用。

50 MiB 是本项目的维护阈值。GitHub 对超过 50 MiB 的普通 Git 文件发出警告，阻止超过 100 MiB 的文件；大型文件可通过 Releases 分发。参见 [GitHub 官方说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。

## 校验约定

`SHA256SUMS` 每行记录一个文件，格式为“64 位小写十六进制 SHA-256 + 两个空格 + 文件名”。Git 内数据使用相对数据集目录的路径，例如 `data/<filename>`；Release 包使用下载文件名。仓库内校验表不包含自身，更新数据时重新计算。

获取说明必须交代校验的工作目录与方法。可使用 PowerShell 的 `Get-FileHash -Algorithm SHA256`，或所在系统提供的 `sha256sum`，比较实际文件的结果与校验表。这里的命令仅说明工具，不代表任何数据已通过验证。
