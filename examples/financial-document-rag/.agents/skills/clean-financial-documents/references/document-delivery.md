# DoclingDocument 交付与验收契约

本页定义通用清洗的终点。文件名可调整，元数据可使用 JSON/YAML；不规定 SQL 表或数据库。

## 最小可重放交付

| 产物 | 应包含的内容 |
|---|---|
| 原始 PDF 或可解析的相对资源定位 | SHA-256、物理页数、语言、页面尺寸/旋转，版本唯一且可核验 |
| raw.docling.json | Docling 原始快照；若分段则保存各段快照与逐页映射，不伪称未解析目录已解析 |
| clean.docling.json | 最终完整 DoclingDocument；保留页面来源、内容节点、父子树、阅读顺序及资产关联 |
| manifest.json | 输入身份、工具/依赖/权重版本、解析配置、页范围、输出哈希、资源相对位置、运行状态 |
| decisions.json | 目录排除、文档样式等级、附件边界、标题补丁、类型转换、引用重映射和证据 |
| repairs.json（有替代解析时） | 原始候选定位与哈希、提供者/配置/任务身份、替换范围、内容差异、接受或拒绝理由 |
| review.json | 最终文档与标题树哈希、实际审阅范围、目录/标题区域证据、预期父子关系、审阅者与未决项 |
| quality.json | 各类检查的计数和定位、失败/排除页、质量例外、接受状态、局部回读与重载结果、成本记录 |

这些是语义字段约定，不要求为了换命名重写项目中已有合法格式。原始/候选快照和必要源区域证据必须能恢复，不能只留下“已接受”布尔值。诊断图像可按源 PDF、区域和渲染参数重建；可恢复的图像不必全部重复保存。

## 清洗文档本身的要求

- 可由实际固定版本的 DoclingDocument 加载并再次序列化，不依赖某个查看器投影才能解释。
- 正文、现有标题、列表、表格、图片和图注等按适用类型保存；图片描述不是必填内容。
- 表格保存完整可用单元格及跨度，不把 Markdown 当唯一事实；图片保存来源区域及原有 caption 引用。
- body、groups、parent、children 等组成一致的有序树。标题应具有正确的显式祖先关系；同名标题使用各自 ref 区分。
- 附件是独立范围时不继承上一附件标题。下游即便使用另一种标题栈，也不能改变这里已验收的树。
- 保留全部原始物理页的定位关系；排除目录是正文范围决定，不改变其他页号。来源精度（字符/节点/区域）如实声明。
- 清洗后的每个内容对象能追踪到原始解析对象或已接受的外部解析候选；结构改动不改写文字、数值和坐标。

## 通过与停止条件

最终状态使用语义明确的分类，具体名称可适配项目：

- **接受**：技术完整性、来源回读和最终标题语义审阅通过，未发现尚存的确定缺陷。
- **带例外接受**：上述检查通过，另有明确范围、原因和影响的未确定风险。需要说明是否影响预期用途，不能等同无误。
- **待修复/部分完成**：保留页解析失败、来源丢失、已确认错误仍存、缺内容或审阅不完整。保留全部结果供续跑，不冒充完整交付。

标题缺失检查与标题关系审阅分别进行：“所有现有标题已审”不能证明没有漏标题。真实无标题文档允许平坦树，空树回执记录为何适用，以及用来排除严重漏标题的原页样式/目录检查依据；不创建伪标题通过程序。

检查结果应分别报告结构完整性、来源有效性、标题语义和内容风险。词项/数字重合率、检查覆盖率都不是全文准确率；不承诺低成本解析能消除所有表格语义错误。

## 脱离原工作目录验证

在另一路径加载 clean.docling.json 和来源清单，验证哈希、schema、引用与父子关系、节点数量，以及原 PDF 的物理页/资产区域回读。使用外部图片资源时核对相对 URI 的解析基准；不能仅移动 JSON 后仍暗中访问旧绝对路径。

不需要 SQLite、Embedding API 或 Agent 问答即可验证此交付。只有用户另行要求知识库存储或混合检索时，才把已验收文档和来源契约交给下游流程；切片与向量不反过来重写文档事实。
