# Docling 解析、风险路由与 MinerU 合并

本页用于决定“什么问题交给什么工具”，不是全文件自动上云的规则。默认由脚本扫描全文并路由，Agent 只审阅目录和标题。以下工具选项以所安装版本为准；版本不支持的能力要明确记录，不能声称已启用。

## Docling 首轮配置

| 输入/目标 | 配置方向 | 必须确认的结果 |
|---|---|---|
| 数字 PDF，文字层可用 | 优先原生文字；本地标准 PDF pipeline | 正文存在、原文与坐标可追踪，多栏顺序没有明显交错 |
| 扫描或文字层损坏 | 启用已安装 OCR 引擎，匹配实际语言；先试问题页 | OCR 恢复文字而非叠加两份文本；页号/坐标不变 |
| 混合文档 | 对扫描/损坏部分做有映射的局部 OCR，或使用已验证的自动选择模式 | 数字页不因重复 OCR 降质，扫描页不被漏掉 |
| 需要表格结构 | 开启 do_table_structure；可从 accurate 模式小样起步 | 单元格、行列跨度和可用表头被保存，不能只剩 Markdown |
| 需要图片节点 | 保留图片类型、原页和区域；按需从原 PDF 渲染裁剪 | 不生成图片文件也可以有可定位图片节点；节点是否存在须单独检查 |
| 需要标题证据 | 读取现有标题级别及可用版面预测、PDF 字体和编号 | 解析器级别只是候选，最终使用显式父子树验收 |

本项目固定版本使用 PdfPipelineOptions/do_ocr、table_structure_options.mode、do_cell_matching 等接口。通用 Skill 不强制 CPU、某种 OCR 或固定模型路径。页图生成、图片文件导出、OCR 和版面中的图片检测是不同功能，不能相互替代。

### OCR 开关的含义

OCR 控制文字识别路径，不是“是否识别表格/图片结构”的总开关。可用原生文字层时关闭 OCR 可以避免重复识别及额外成本；扫描页关闭 OCR 则可能缺失文字。表格结构、单元格匹配及图片区域仍需各自检查。

MinerU 每文件的 is_ocr、模型选择及其实际作用取决于所选服务版本。执行时保存请求清单，核对当前官方接口并做小样；不要把本地 Docling 的 do_ocr 语义机械复制到另一后端。不能承诺 is_ocr=false 会禁止视觉模型读取图中文字，也不能由此推断表格/图片节点一定正确。

## 不依赖 Agent 全文阅读的风险检测

自动检测输出“原页、区域、ref、指标、缺陷类别、建议动作”。保留页全部纳入检测；阈值由小样校准并记录。至少检查：

- 覆盖：保留的非空页没有内容、页码越界、段落来源缺失、跨页字符跨度不合法。
- 正文：乱码/替代字符异常、原生文字与解析词项明显不一致、重复文本、跨栏混排的几何冲突。
- 表格：数字密集且有行列对齐的区域没有表节点；空表；单元格跨度非法/重叠；同一区域数字或文字大量未分配；列数和表头关系异常；续表突然丢列。
- 图片：PDF 图像或绘图区域缺少对应节点；图片与表格区域重叠；空表区域疑似图示；caption 与目标资产错页/距离异常。
- 标题：目录条目漏对应、候选级别跳变、页眉/表题误识别、附件范围之间继承标题、容器内标题未进入树。

PDF 的嵌入图片数量不等于语义图片数量：一张图可能由多个位图或矢量绘图组成，logo/背景也可能只是装饰。不能将每个 image xref 自动变成正文图片。数字/文字覆盖、表头缺失和几何评分都是诊断信号；原生 PDF 提取本身也会错序，不作为绝对正确答案。

## 解析路线决策

用户未指定时，全量 Docling 是默认基线。先用本地脚本和代表页诊断实际缺陷，再按范围选择路线：

| 观察到的情况 | 路线 | 操作与停止条件 |
|---|---|---|
| 未见解析缺陷，或仅需标准结构化解析 | **全量 Docling** | 按已验证配置解析保留页，冻结原始快照，继续标题/来源验收。 |
| 扫描页空白、文字层损坏，或局部表格/版面问题有可试的 Docling 设置 | **Docling 局部重试** | 只对问题页和必要邻页试适用的 OCR、PDF 后端或表格选项。每次独立保存候选；有效则沿用 Docling，否则转下一行。 |
| 正文、阅读顺序、表格或布局缺陷可定位，且本地重试仍失败或不适用 | **MinerU 局部候选** | 经授权后只提交问题页及必要邻页，和同页 Docling/原页对照；采纳范围限于可映射并通过质量检查的内容。 |
| 多类代表页反复出现同类缺陷，或用户在考虑全量替代 | **MinerU 样页比较，再由用户选择是否全量** | 先核实样页外发授权，最多选 8 页覆盖已发现的缺陷类型并和 Docling 比较。报告结果、未覆盖类型、全量页数、外发范围和可核实成本。只有用户明确选择全量 MinerU 并授权后才提交整批。 |

样页数量是初始对照上限，不是质量通过阈值。缺陷类型超过样页所能覆盖的范围时，如实标为未验证；扩大样本需要先重新核实授权和预算。明确的单页缺陷本身不构成全量切换理由。全量路线始终保留 Docling 原始快照，MinerU 结果作为独立候选进入统一 DoclingDocument 契约及最终验收。

### 根据症状分流

| 已定位症状 | 处理方式 |
|---|---|
| 标题文字正确但父级错误 | 核对编号序列、目录、样式和附件上下文，修结构决定；不单凭层级错误重跑解析。 |
| 扫描页或损坏文字层无文字/漏字 | 先选语言匹配的 Docling OCR/后端候选；局部结果仍损坏时，比较 MinerU 对应页。 |
| 表格区域存在但单元格为空、漏表、明显错列或合并跨度错 | 先核实原页区域并试局部 Docling 表格候选；失败时转 MinerU 页候选，逐项比较关键内容与行列关系。 |
| 多栏正文混排、页面块顺序错或导航压入正文 | 用原页图像判别正文和家具/导航，再对照局部候选；仅在重复出现在多种代表页面且样页结果更可靠时考虑全量路线。 |
| 空表实际是流程图/组织图 | 核实区域后将其保留为图片节点；不用 MinerU 文本候选替代图像来源。 |
| 只有“表很大/很宽”、缺少声明表头或覆盖指标异常 | 这些是复查信号，不单独触发 MinerU 或全量解析；先核验具体内容缺陷。 |

选择一个与症状相符的本地候选，避免盲目遍历配置。比较原页时不把 PDF 原生文本当作绝对正确：原生文字层也可能缺字或错序。一次只检验有限候选，持续使用同一原页证据。

## MinerU 的范围、输入与输出

使用具有结构化版面/表格输出的精准解析接口。执行前确认当前接口、模型、语言、表格/公式选项、页限制、权限和已授权额度；保存真实参数和服务返回版本，不自动升级模型或增加付费范围。项目已验证调用方式在 project-adapter.md，不能视为所有版本的固定默认。

局部路线默认抽取问题页；跨页表格、续表或边缘截断时加入必要邻页。全量路线提交所有保留正文页，并按当前服务限制分包。两种路线的纯目录页都不因邻页扩展重新进入正文候选。每个提交文件保存 PDF 哈希及逐页映射，包括抽取、分段、旋转和裁剪变换。跨页上下文应尽可能保持连续，不能只截出半个表格。

保存任务 ID、状态、请求身份、下载包校验值和原始结构化输出。结果未知先查状态；相同页段/参数命中缓存则不重复上传。拒绝仅凭 Markdown 推造单元格坐标或页码。

MinerU 全量分支只指经当前验证的云端 API 路线，不假设本地 MinerU 已安装。进入全量提交前必须同时满足：代表样页中目标缺陷有实质改善；样页覆盖的内容、结构和来源可核验；服务版本、全量页数、外发范围与可核实成本已告知用户；用户明确选择并授权。未满足任一项则保持 Docling 全量或采用已验证的 MinerU 局部候选，不由 Agent 根据“缺陷看起来系统性”自行切换或提交。

全量提交时仍保留 Docling 原始快照及 MinerU 原始结构化结果。将正文、标题、表格单元格/跨度、图片/图注、阅读顺序、页号和坐标映射为候选 DoclingDocument，并保留原始到候选的来源映射。不能将纯 Markdown 当成有来源的 DoclingDocument。转换器遇到不支持的 schema/节点、无法闭合的页映射、越界坐标或来源丢失时，停止候选合并并报告具体阻断原因；不丢弃未知内容来强行通过。全量替代后执行与 Docling 路线相同的内容、来源、表格风险和完整标题树验收；更换解析器不会自动修正标题语义。

## 转换、匹配和接受

1. 验证支持的结果 schema/版本，读取包含页内区域的结构化输出。局部和全量 MinerU 分支都转换正文、标题、表格、图片和关联 caption/footnote，不只导入文本。
2. 把所有局部页号和坐标转回原始物理页、统一坐标原点/单位；记录提供者节点 ID 到 Docling ref 的映射。不明来源的内容不合入通过版本。
3. 通过同页几何位置与内容确认同一对象。优先替换受影响表格或区域，保持其他正文、标题及阅读顺序。匹配不唯一、一表被拆为多块或区域越界时，不套用简单一对一覆盖。
4. 表格保留单元格、rowspan/colspan、表头角色和图注。至少比较关键数字及文字覆盖、行列数量、跨度、表头对齐、是否截断；必要时在受控范围核对原表区域。这个范围由脚本/局部人工检查负责，不默认交给标题 Agent 逐表阅读。
5. 用原页视觉证据检查目标缺陷是否改善，并复查正文遗漏/重复/顺序、关键数字、表格行列/表头、图片与图注。数值/文字覆盖只能辅助定位；下降或仍有明显错列时拒绝候选，无法判定时保留原版与风险。记录具体接受/拒绝依据，几何阈值不能证明语义正确。
6. 重写受影响的 ref、父子和图注引用，保存原始对象、候选、最终对象之间的对应。检查没有双重保留同一内容或误删相邻正文。若改变了标题、节点顺序或祖先范围，返回标题树核验。
7. 生成符合 DoclingDocument schema 的候选并重新加载验证。结构不变性与解析内容差异分别检查，不能用“标题没变”证明表格值正确。

页内区域优先于未经核验的跨页表自动合并。关联跨页表时保存各页来源；证据不足可保留多个续表节点，不把后页单元格全部绑到首页。缺少单元格坐标时保留表区域级精度，不合成框。

## 来源与内容验收

扫描全部 ref 的引用闭合、循环、重复父归属、父子双向一致、阅读顺序与脱离正文树的内容。结构容器可无自身几何位置，实际正文/表格/图片必须有可追踪来源；图表内部标题与图注仍应可达。

内部 page_index 为零基，展示物理页 page_number 为一基，二者相差 1；印刷页码另记。Docling prov.page_no 对应原始物理页，不对整个文档套固定印刷页偏移。坐标须在对应页范围内；跨页文本逐段 charspan 和来源保留。

比较原始与清洗快照，仅允许声明过的导航处理、类型/结构变换和已接受的解析替换。被移出正文的导航在原 PDF/快照及排除清单中可追溯。实际执行各类内容的原页/区域回读；进程返回 success 不等于通过内容验收。最终接受状态及机器记录见 document-delivery.md。
