# v2 事实与下一轮实验设计

[项目首页](README.md) · [操作](OPERATIONS.md) · [验收](VALIDATION.md)

## 从 PDF 到可核查事实

六份财报先固定 PDF 哈希、物理页号和解析配置，再保存原始与整理后的 DoclingDocument。清洗对目录、标题层级、阅读顺序、表格与图片做可重放决定；每个保留节点可以回到原 PDF 页。最终标题树的审阅回执绑定到候选快照，避免把脚本通过误当作语义审阅。清洗不读取问题、答案或相关性标签来决定文档事实。

事实版本由源 PDF、快照、配置与审阅结果共同约束。v2 事实库只发布被接受的版本；新解析器或局部修复先作为独立候选，经过原页和来源核查后才可能产生新的发布 ID。检索层记录所消费的事实发布 ID，避免把旧切片套在新事实之上。SQLite 包装快照和节点关系，原 PDF 仍是单独校验的外部输入。

## 检索与回读

A 直接读取 PDF 原生文字，递归切到目标 token 预算并带重叠。B 从已审阅的结构节点出发，使用 HybridChunker 和同章节短段合并；图片、表格形成边界，多层表头在相关切片中重复。两组使用各自的 FTS5 与向量入口，以 RRF 融合排名。标题路径先从事实树取得，再进入检索文本。

`chunk_items` 将命中切片关联回节点；阅读工具按来源读取原文和物理页图像。跨页正文按文本跨度定位页，矩形精度仍按已保存的节点证据表述，不制造更精确的坐标。没有描述的图片保持可回读的事实资产，但 B 不为它虚构可检索说明。

C 在同一事实基础上保留 B 的所有原始检索片段，再增加图像描述和整表摘要。同一图表的多个命中按来源分组，取最佳片段的融合分数，不把重复入口当成额外投票；相关原始片段仍可回读。生成摘要只用于定位，不能作为回答证据。旧的替换模式只作为显式消融选项保留。

下一轮 A 直接把召回的原始切片交给模型，不再自动扩成整页或加入图片。B/C 先读取全部高排名命中片段，再用剩余预算扩展同章节上下文；图表可读取原页图像。正文使用已经保存的片段文字和来源，避免把 raw.orig 的字符偏移错误套到规范化文本；多页表格的部分文字仍保守计算页覆盖率。

D 沿用 C 的索引，先读两个来源，再按公司、年份、指标、单位及计算条件构造证据缺口，决定继续 search/read。预览另设预算，不再挤占原文。首次检索指标与 C 可比，另记录所有搜索的页并集召回和最终实际阅读覆盖。并集召回不代表有统一的最终排序。

共享默认值：两路各 50 候选、RRF 常数 60、融合后最多 20 个来源组；切片仍为 800 token。原文预算 24,000 token、预览总预算 3,000 token、每次读取最多 2,400 token、最多 8 张原页图。D 最多 10 个逻辑模型轮次和 20 次工具操作（包含初始搜索和种子阅读）。每个逻辑调用的 JSON/协议验证最多重试 5 次，首次请求加重试最多 6 次；所有物理请求另记账，不能把逻辑轮数当请求数。HTTP 400/401 等确定性错误不盲重试，暂时性服务错误受配置和同一尝试上限约束。

这些是完整方案比较，A 的证据形态以及预算均与上一轮有变化；不能将新旧准确率差异归因于单个修复，也不预设 A<B<C<D。

当前仓库随 LFS 发布的仍是 v2 事实和 A/B 检索层；新的 C 需重建增强索引。外部全量结果包已审阅，但完整增强缓存未回传本机。新实现的修复与诊断见[修复报告](REPAIR_REPORT_20260929.md)，事实发布规模和历史验收见[当前验收](VALIDATION.md)。
