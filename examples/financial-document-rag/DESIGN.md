# 当前 v2 设计

[项目首页](README.md) · [操作](OPERATIONS.md) · [验收](VALIDATION.md)

## 从 PDF 到可核查事实

六份财报先固定 PDF 哈希、物理页号和解析配置，再保存原始与整理后的 DoclingDocument。清洗对目录、标题层级、阅读顺序、表格与图片做可重放决定；每个保留节点可以回到原 PDF 页。最终标题树的审阅回执绑定到候选快照，避免把脚本通过误当作语义审阅。清洗不读取问题、答案或相关性标签来决定文档事实。

事实版本由源 PDF、快照、配置与审阅结果共同约束。v2 事实库只发布被接受的版本；新解析器或局部修复先作为独立候选，经过原页和来源核查后才可能产生新的发布 ID。检索层记录所消费的事实发布 ID，避免把旧切片套在新事实之上。SQLite 包装快照和节点关系，原 PDF 仍是单独校验的外部输入。

## 检索与回读

A 直接读取 PDF 原生文字，递归切到目标 token 预算并带重叠。B 从已审阅的结构节点出发，使用 HybridChunker 和同章节短段合并；图片、表格形成边界，多层表头在相关切片中重复。两组使用各自的 FTS5 与向量入口，以 RRF 融合排名。标题路径先从事实树取得，再进入检索文本。

`chunk_items` 将命中切片关联回节点；阅读工具按来源读取原文和物理页图像。跨页正文按文本跨度定位页，矩形精度仍按已保存的节点证据表述，不制造更精确的坐标。没有描述的图片保持可回读的事实资产，但 B 不为它虚构可检索说明。

C 在同一事实基础上为图像和整表加入检索用描述或摘要；增强文本不替代原始节点，回答仍须回读来源。D 沿用 C 的索引，让模型在预算内决定继续 `search` 或 `read`。四组的处理差异是完整方案差异，包括解析与切片；不能将结果简单归因于单一组件。

当前真实六份财报只发布 A/B。C/D 已有虚构夹具的控制流验证，真实数据的全量增强与索引尚待完成。发布规模、已知缺陷和验证边界统一见[当前验收](VALIDATION.md)。
